# Soler 言語カタログ実装ルール

## 目的

将来、多言語対応が必要になったときに大きな作り直しが発生しないよう、利用者向けの表示文言をLaravelの言語カタログへ分離する。

現段階では日本語カタログだけを用意し、英語への翻訳や言語切り替え機能は実装しない。

---

## 現段階の方針

- `lang/ja`だけを用意する
- 新しく追加する利用者向け文言は、原則として言語カタログへ置く
- DBやモデルの内部値を日本語の表示文言に依存させない
- 既存コードは一括置換せず、修正する箇所から段階的に移行する
- 英語カタログや言語設定は、実際に必要になってから追加する

---

## 実装ルール

### 1. 画面文言を直接記述しない

BladeやLivewireでは、原則として翻訳キーを使用する。

```php
{{ __('transactions.fields.transaction_date') }}
```

```php
<?php

return [
    'fields' => [
        'transaction_date' => '取引日',
        'amount' => '金額',
    ],
    'actions' => [
        'register' => '登録する',
    ],
];
```

利用者に表示されないログや、一時的なデバッグ文言までカタログ化する必要はない。

### 2. 日本語を翻訳キーにしない

キーには文言ではなく、意味を表す名前を使用する。

```php
__('fiscal_years.status.closed')
```

次の形式は使用しない。

```php
__('締め済み')
```

### 3. 内部値は言語に依存させない

DBへ保存するステータス、種別、区分などには、言語に依存しない値を使用する。

```text
unknown
qualified
non_qualified
```

表示するときだけカタログを使用する。

```php
__('counterparties.qualification_status.'.$status)
```

会計計算、検索、条件分岐で翻訳後の日本語を使用しない。

### 4. ユーザー入力値は翻訳しない

次の値は、ユーザーが入力した内容をそのまま保存・表示する。

- 取引先名
- 摘要
- メモ
- カスタム勘定科目名
- カスタム補助科目名

### 5. Solerが用意する表示文言をカタログ化する

原則として、次の文言をカタログへ置く。

- 画面タイトル
- フォームラベル
- ボタン名
- ステータスの表示名
- 入力補足
- バリデーションメッセージ
- 利用者向けエラーメッセージ
- Soler標準の選択肢
- Soler標準の名称や説明

既存の標準勘定科目名などがDBに保存されている場合は、現段階で一括変更しない。
ただし、新しい処理では名称そのものを検索条件や判定条件に使用しない。

### 6. ドメインロジックと表示文言を分ける

モデルやサービスでは、表示用の日本語を条件分岐に使用しない。

```php
if ($status === FiscalYear::STATUS_CLOSED) {
    // ...
}
```

利用者向けメッセージは、画面側でカタログから取得する。

### 7. カタログは機能単位で分ける

すべてを`messages.php`へ集約せず、必要になった機能からファイルを追加する。

```text
lang/
└── ja/
    ├── common.php
    ├── accounts.php
    ├── transactions.php
    ├── counterparties.php
    ├── fiscal_years.php
    └── validation.php
```

空のファイルを最初から大量に作る必要はない。

---

## キーの命名

原則として、次の形式にする。

```text
機能.分類.項目
```

例：

```text
transactions.fields.amount
transactions.actions.register
transactions.messages.registered
transactions.errors.fiscal_year_closed
fiscal_years.status.open
fiscal_years.status.closed
```

同じ日本語でも意味や用途が異なる場合は、無理に共通化しない。

`common.php`には、「キャンセル」「閉じる」「はい」「いいえ」など、機能をまたいでも意味が変わらない短い文言だけを置く。

---

## バリデーション

Laravel標準のバリデーション文言は、`lang/ja/validation.php`を使用する。

項目名は`attributes`へ定義する。

```php
<?php

return [
    'required' => ':attributeを入力してください。',
    'attributes' => [
        'transaction_date' => '取引日',
        'amount' => '金額',
    ],
];
```

特定の機能だけで使用するメッセージは、その機能のカタログへ置いてよい。

---

## 既存コードの移行

既存の日本語直書きは、次のタイミングで段階的に移行する。

1. 新しい機能を追加するとき
2. 既存画面を大きく修正するとき
3. 同じ文言の重複が問題になったとき
4. 実際に多言語対応を開始するとき

文言の置き換えだけを目的とした大規模な修正は、現段階では行わない。

---

## 現段階では行わないこと

- 英語カタログの作成
- 言語切り替えUI
- ユーザーごとの言語設定
- 帳票の多言語化
- ユーザー入力内容の自動翻訳
- 既存文言の全面的な置き換え
- 未実装機能を前提としたカタログ設計

まずは、日本語だけでも表示文言と内部ロジックが分離された状態を維持する。
